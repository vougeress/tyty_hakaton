# Tutu Окно

Мобильный планировщик совместных поездок: участники ведут общий календарь, находят свободные окна, добавляют события, выбирают идеи голосованием, проверяют логистику и сохраняют бронирования.

Проект сделан на Next.js 16, React 18, TypeScript, PostgreSQL 16 и Drizzle ORM. Для подбора мест рядом используется GigaChat, для поиска транспорта и повторной проверки вариантов — публичный Tutu MCP.

Инструкция по работе с интерфейсом без технических деталей находится в [пользовательском руководстве](USER_GUIDE.md).

## Что умеет приложение

- поездка и локальный выбор текущего участника;
- недельный календарь с личными и общими событиями;
- вычисляемые свободные окна;
- ручное добавление события сразу в план или через голосование;
- подбор достопримечательностей рядом через GigaChat;
- поиск транспорта через Tutu MCP с резервным demo-каталогом;
- голосование `За / Можно / Не могу`, досрочное завершение и переголосование;
- повторная проверка победителя, переход на Туту и подтверждение бронирования;
- аудит конфликтов и недостающих переездов;
- сохранение событий, голосований, бронирований и черновиков в PostgreSQL.

## Требования

- Node.js 20.9 или новее;
- npm;
- Docker Desktop или Docker Engine с Compose;
- свободные порты `3000` для приложения и `5433` для PostgreSQL;
- ключ GigaChat API — нужен для live-подбора достопримечательностей.

## Быстрый запуск

```bash
git clone <repository-url>
cd tyty_hakaton

npm ci
cp .env.example .env
```

Откройте `.env` и вставьте ключ GigaChat:

```dotenv
DATABASE_URL=postgresql://tutu_okno:tutu_okno@localhost:5433/tutu_okno

GIGACHAT_AUTH_KEY=ваш_authorization_key
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_MODEL=GigaChat-2-Pro

TUTU_MCP_URL=https://mcp.tutu.ru/mcp
```

Затем запустите базу и подготовьте демо-данные:

```bash
docker compose up -d postgres
npm run db:migrate
npm run db:seed
```

Запустите приложение:

```bash
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000).

Seed можно запускать повторно: он идемпотентный. Он создаёт поездку «Казань», четырёх участников, календарные события, голосование и архивные поездки. Код приглашения демо-поездки — `KAZAN2026`.

## Как получить ключ GigaChat

1. Откройте [официальный быстрый старт GigaChat API](https://developers.sber.ru/docs/ru/gigachat/individuals-quickstart).
2. Войдите в личный кабинет Studio и создайте проект GigaChat API.
3. В проекте откройте **Настройки API**.
4. Нажмите **Получить ключ** и скопируйте значение **Authorization Key**.
5. Запишите его в `.env` как `GIGACHAT_AUTH_KEY`.

Authorization Key показывается только при создании. Не добавляйте `.env` в git и не отправляйте ключ в сообщения или скриншоты.

Приложение самостоятельно обменивает Authorization Key на access token и кеширует его до истечения срока. Вручную получать токен обычно не нужно. Для короткой проверки можно вместо ключа установить `GIGACHAT_ACCESS_TOKEN`, но такой токен действует около 30 минут. Подробности есть в [официальной документации по авторизации](https://developers.sber.ru/docs/ru/gigachat/api/reference/rest/gigachat-api).

В репозитории уже есть публичный корневой сертификат `certs/russian_trusted_root_ca.pem`. Команды `dev`, `build` и `start` автоматически подключают его через `NODE_EXTRA_CA_CERTS`.

## Tutu MCP

По умолчанию приложение обращается к публичному endpoint:

```dotenv
TUTU_MCP_URL=https://mcp.tutu.ru/mcp
```

На момент разработки токен для публичного endpoint не требуется. Если конкретное окружение потребует авторизацию, клиент поддерживает переменную `TUTU_MCP_TOKEN`.

В обычном режиме сначала выполняется live-запрос к MCP. Если сервис недоступен или не вернул подходящих вариантов, приложение переключается на резервный demo-каталог и показывает предупреждение в интерфейсе.

## Переменные окружения

| Переменная | Обязательна | Назначение |
| --- | --- | --- |
| `DATABASE_URL` | да | Подключение к PostgreSQL. Значение из `.env.example` подходит для Compose. |
| `GIGACHAT_AUTH_KEY` | для live GigaChat | Долгоживущий Authorization Key из проекта GigaChat API. |
| `GIGACHAT_SCOPE` | нет | `GIGACHAT_API_PERS`, `GIGACHAT_API_B2B` или `GIGACHAT_API_CORP`. По умолчанию — `PERS`. |
| `GIGACHAT_MODEL` | нет | Модель GigaChat. По умолчанию — `GigaChat-2-Pro`. |
| `GIGACHAT_ACCESS_TOKEN` | нет | Короткоживущая альтернатива Authorization Key для быстрой проверки. |
| `GIGACHAT_API_URL` | нет | Переопределение API URL. По умолчанию — `https://api.giga.chat`. |
| `GIGACHAT_OAUTH_URL` | нет | Переопределение OAuth URL. |
| `TUTU_MCP_URL` | нет | Адрес Tutu MCP; публичный адрес уже используется по умолчанию. |
| `TUTU_MCP_TOKEN` | нет | Bearer token для MCP, если он требуется окружением. |
| `E2E_MOCK_MODE` | только тесты | Включает mock fixtures и визуальные presets. Не используйте в обычном запуске. |
| `TUTU_LIVE_TEST` | только тесты | Разрешает opt-in интеграционный тест публичного Tutu MCP. |

## Как пользоваться

1. На экране поездок выберите текущую поездку и участника. В MVP это локальная persona в `localStorage`, полноценной авторизации нет.
2. Откройте календарь. Фильтр **Я** показывает события выбранного участника, остальные фильтры — события попутчиков.
3. Нажмите на свободное окно:
   - **Добавить вручную** — создайте событие сразу или отправьте его на голосование;
   - **Подобрать варианты** — найдите транспорт по направлению через Tutu MCP;
   - **Места рядом** — получите идеи достопримечательностей через GigaChat.
4. Выберите варианты и создайте голосование. Ответ можно менять до закрытия; создатель или владелец поездки может завершить голосование раньше.
5. После выбора победителя перепроверьте цену и места, откройте ссылку Туту и подтвердите покупку. Подтверждённое бронирование появится в календаре после обновления.
6. Нажмите **Проверить** в календаре, чтобы найти конфликты и недостающие переезды. Предложенные переезды сначала сохраняются как черновики.

## База данных

Проверить состояние контейнера:

```bash
docker compose ps
```

Открыть Drizzle Studio:

```bash
npm run db:studio
```

После изменения `db/schema.ts`:

```bash
npm run db:generate
npm run db:migrate
```

Полностью удалить локальную базу и создать её заново:

```bash
docker compose down -v
docker compose up -d postgres
npm run db:migrate
npm run db:seed
```

Команда `docker compose down -v` необратимо удаляет локальный Docker volume проекта.

## Частые проблемы

### PostgreSQL не запускается

Проверьте, не занят ли порт `5433`:

```bash
docker compose ps
```

Если на порту уже запущен контейнер этого проекта, используйте его. Не запускайте второй Compose project с тем же портом.

### GigaChat отвечает `401`

- убедитесь, что в `GIGACHAT_AUTH_KEY` находится Authorization Key, а не access token;
- приложение само добавляет префикс `Basic`, поэтому в `.env` допустим ключ как с ним, так и без него;
- проверьте `GIGACHAT_SCOPE`: тип scope должен соответствовать созданному проекту.

### Подбор мест рядом не работает, а остальное приложение работает

Это ожидаемо при пустом или недействительном `GIGACHAT_AUTH_KEY`. Календарь, ручные события, PostgreSQL и Tutu MCP продолжают работать независимо.

### Tutu показывает резервные варианты

Live MCP не ответил или не нашёл маршрут под заданное окно. Интерфейс явно помечает переход на резервный каталог; это не считается подтверждённой live-выдачей.

## Безопасность локальной конфигурации

- `.env` и `.env*.local` исключены из git;
- в `.env.example` должны находиться только пустые значения и публичные URL;
- не коммитьте access tokens, Authorization Keys, дампы БД, `data/uploads`, `.next`, `playwright-report` и `test-results`;
- текущий выбор участника хранится в `localStorage` и предназначен для локального MVP, а не для публичной авторизации.
